# MOVE/MIX 多平台中文版

边练边看，随心组合。纯 HTML / CSS / JavaScript 静态网站。

这是第三个独立项目：不是原 YouTube 专用 MOVE/MIX 的更新，也不是 Bilibili Compatibility Lab 的更新。界面参考原版米白、青柠绿、淡紫色的设计语言；播放器架构独立实现。不要把这些文件复制到任何旧项目目录，也不要替换旧 ZIP 或旧 GitHub Pages 部署。

## 本地打开

将最新版 move-mix-cn-v4.zip 解压到新目录，在含 index.html 的目录打开终端：

```
python -m http.server 8766
```

浏览器打开 http://localhost:8766 。需联网访问视频平台。请通过 HTTP / HTTPS 访问，不推荐双击 file:// 文件：YouTube 播放器验证依赖正常的网页来源和 Referrer。Python 只提供静态文件，不是应用后端，无需构建、密钥或安装依赖。

## 独立部署 GitHub Pages

1. 新建单独的 GitHub 仓库，例如 move-mix-cn。不要使用两个旧项目的仓库。
2. 将 index.html、styles.css、app.js、README.md 上传到新仓库根目录。tests 文件夹可一并上传，运行网站不依赖它。
3. 在这个新仓库的 Settings → Pages 选择 Deploy from a branch，main 分支，根目录。
4. 使用 GitHub 显示的新 Pages 地址。三个项目可以同时保留。

## 使用

输入锻炼、娱乐两个链接，平台自动识别，点击“开始”。默认娱乐大屏、锻炼浮动小窗，锻炼静音默认开启。已加入你提供的运动推荐与浏览器本地收藏；没有账号连接、平台搜索或数据库。支持手动批量导入队列与YouTube官方播放列表。

支持四种按角色排序的组合：YouTube × YouTube、YouTube × Bilibili、Bilibili × YouTube、Bilibili × Bilibili。两个角色独立解析、独立创建适配器，不硬编码平台顺序。

支持链接：

- youtube.com/watch?v=11位视频ID
- youtu.be/11位视频ID
- YouTube 的 m.youtube.com、/shorts/、/embed/、/live/ 单视频形式
- bilibili.com/video/BV加10位字母数字/；保留合法 p 参数选择分P
- 可省略 https://，自动按 HTTPS 解析

不自动解析 b23.tv 短链，也不读取收藏夹或平台页面；短链请改用完整视频链接或BV号。YouTube官方播放列表现已支持，详见下方v2更新。无效输入会显示中文提示，不会进入播放页或影响另一输入框。

交换画面、小窗四角位置、网站内部沉浸模式只改变 CSS 布局，不移动或重新创建 iframe，也不重置计时器。沉浸模式不调用平台原生全屏；点击退出或按 Escape 返回。平台自带的单视频全屏由平台控制，可能不保留双屏。

“更换视频”停止计时、恢复临时音频状态并销毁两个播放器，避免隐藏页面继续出声。保留网址和锻炼静音选择，方便只改一个链接。再次开始时重新载入视频，播放进度不保留。输入与静音选择使用独立命名的本地存储键 move-mix-cn:setup:v1；存储不可用时仍可正常使用当前会话，不读取旧项目的存储。

## Player Adapter 架构

app.js 包含 PlayerAdapter、YouTubePlayerAdapter、BilibiliPlayerAdapter、createAdapter。每个实例明示以下 capabilities：

| 能力 | YouTube | Bilibili |
| --- | --- | --- |
| canPlayProgrammatically | true | false |
| canPauseProgrammatically | true | false |
| canMuteProgrammatically | true | false |
| canSetVolume | true | false |
| canGetCurrentTime | true | false |
| canDetectEnded | true | false |
| canSeek | true | false |

true 表示采用官方文档支持的父页面接口，实际调用仍检查 ready 状态；不表示所有设备、视频和音量策略均已验证。Bilibili 的 false 表示当前未验证到可用的官方父页面方法。未实现的方法返回 false，时间与音频状态等读取返回 null；不发送猜测的 postMessage 指令。

YouTube 使用官方 https://www.youtube.com/iframe_api 和 YT.Player，封装 playVideo、pauseVideo、mute、unMute、setVolume、getCurrentTime、getPlayerState、seekTo，接收 ready/state/error/ended 事件。参数为 playsinline=1、autoplay=0、controls=1、origin=网页来源；就绪后应用初始静音和音量。用户点击“同时播放”才发送播放请求。手机是否同时播放、同时发声，以及音量控制效果，仍受设备政策限制。

Bilibili 仅使用官方 https://player.bilibili.com/player.html ，构造以下官方记录的参数：

- bvid：提取的 BV ID；av号则使用官方 aid 参数，二者只传其一
- p：仅在链接给出合法正整数时保留
- autoplay=0：不依赖初始自动播放
- muted=1 / 0：初始静音请求
- danmaku=0：请求关闭弹幕

URL 初始参数与运行时控制是不同能力。B站 iframe 加载事件只更新“请使用底部控件”，不表示视频可播放、已静音或已播放。本次浏览器观察中，平台自身对弹幕等选项的实际呈现未必与页面预期一致，参数效果请在具体视频和设备上核对。

“同时播放”只调用可控制且就绪的 YouTube 适配器；有B站时提示“请点击 B站播放器开始播放”。“全部暂停”只暂停可控制的 YouTube 播放器；有B站时提示“B站播放器需要在播放器控件中手动暂停”。不会宣称B站已被暂停。

运行时切换“锻炼静音”：YouTube 直接调用 API。B站显示明确的“重新载入锻炼视频以应用”按钮，点击才替换锻炼 iframe，进度会重置，娱乐 iframe 不重建；如果把选择改回当前加载值，重载按钮隐藏。仅切换复选框不会假装静音已生效。

## B站点击画面跳转调查

本项目及实验室的父页面没有为 iframe 外层添加导航链接、点击跳转处理或覆盖整个 iframe 的透明层；新版标题条在视频区域之外，iframe 保留指针与触摸交互。CSS 的大小窗布局本身不创建跳转目标。

官方外链播放器可显示视频标题、作者、平台入口和内容推广入口；这些界面由B站提供。官方参数文档未提供经验证的“关闭画面点击跳转”选项，也没有提供父页面暂停 API。因此不能把用户遇到的所有跳转归因到同一个内部事件，更不能承诺父页面能修复。

本次桌面浏览器用官方文档示例 BV1B7411m7LV 进行了有限观察：点击底部“播放/暂停”控件后视频时间前进，再点击该控件后出现暂停界面，主页面仍为本地 MOVE/MIX 地址。该结果只覆盖这个样例、当前平台版本与本次浏览器，不保证每个视频或设备都如此。没有通过画面点击主动重现所有跳转路径，也没有检查或操纵跨域播放器内部脚本。正式 app 不访问 iframe 内部 DOM。

界面保留简短提示，引导使用底部控件，并把可控的 YouTube 操作留在 MOVE/MIX 控制区。需要重新加载或换链接时可使用页面按钮；无法从父页面保证B站所有点击都不导航。

## 快速计时

30 / 45 / 60 按钮点击立即开始；“＋”可输入 1–3600 的整数秒数。没有第二个启动步骤（自定义秒数除外）。计时使用独立的结束时间戳减 Date.now()，不读取任何视频 currentTime。交换、沉浸、大小屏变化不影响计时。后台回调延迟后会按真实经过时间更新；返回前台时主动刷新，已过期就直接完成，不补发迟到的静音提示。浏览器后台运行限制仍会影响视觉更新时机；系统时间被人为调整会影响基于时间戳的倒计时。

娱乐是 YouTube 且已就绪时，最后约 1.5 秒保存当时的 volume/mute 状态并临时静音；0秒、取消或离开时恢复原状态。此段期间禁用页面娱乐音量滑杆，避免其设置与恢复冲突。播放器内部的临时手动音量变化会被原状态恢复覆盖。若未就绪则跳过音频提示。

娱乐是 Bilibili 时，计时照常进行，最后两秒用高亮视觉提示，结束显示“完成”。不控制其音量、不暂停、不重载、不增加其他音频源。开启系统减少动态效果时保留高亮，不使用脉动动画。

返回选择、手动重新加载娱乐视频或离开网页会取消计时并恢复 YouTube 临时音频状态；仅重新加载锻炼视频不重置计时。

## 错误与移动布局

YouTube 的常见无效、权限、禁止嵌入、验证和加载错误显示中文消息并可独立重试，不移除另一个播放器。API 连接超时后可重试。

B站跨域 iframe 无法向本页面可靠报告媒体权限、删除、网络和内容错误。仅在浏览器实际触发 iframe error 时显示加载错误；其余错误请查看官方播放器。页面始终提供单独重载与更换链接入口，不伪造自动成功或失败。

桌面、平板、手机均保留大屏＋浮动小窗。小窗标题与 iframe 分开，视频区域至少 200×200 像素；手机使用较高的主播放区承载浮窗，而不是压缩为极小缩略图或简单上下堆叠。屏幕很小时可交换画面看清小窗内容，或开启沉浸模式。小窗默认位于左上角，可选择四角并通过滑杆调整大小；尺寸受屏幕可用宽度限制。页面包含安全区留白与至少44像素的主要触摸控件。

### 粘贴更方便

每个角色输入框都支持多行，每行一项，最多100项：

```
【视频标题】https://www.bilibili.com/video/BV1B7411m7LV/
BV1B7411m7LV
av170001
https://youtu.be/M7lc1UVf-VE
```

示例只说明格式，不是默认推荐。可直接粘贴B站“标题＋https链接”，自动提取网址，标题与链接分成两行也可以；BV/av号无需补网址。普通文字行会忽略，网址和视频号按输入顺序提取；无效的网址项会指明位置并阻止整批载入，避免错误导入。每行也可包含多个以空白隔开的链接或视频号。

b23.tv 是重定向短链，短码本身不含可供官方播放器使用的BV/av号。当前纯静态站没有经验证的官方短链展开方法，因此显示中文提示，让用户先打开短链并复制完整地址或BV号。不抓取页面、不依赖第三方短链代理，也不把短链冒充可播放视频。

### 队列与合集

锻炼和娱乐各有自己的队列，支持YouTube与B站混排。播放页可用上一项、下一项或下拉列表直接选择，只重新加载该角色的播放器。切换娱乐会先取消计时并恢复临时声音；切换锻炼不影响计时。

单个YouTube视频结束后，收到官方 ended 事件自动进入该角色下一项。下一项是YouTube时就绪后发送播放请求；如果浏览器拦截，会提示用户手动开始。下一项是B站时只加载官方iframe，仍需手动点击播放。

YouTube 合集支持 youtube.com/playlist?list=... 以及带有效 list 参数的视频链接。使用官方 cuePlaylist（首次加载）或 loadPlaylist（队列接续）交由YouTube管理合集内联播，不使用Data API、不抓取列表。首次从合集第1项开始。合集内部每条视频结束时不会误跳到页面队列下一项；整个合集结束后使用页面的“下一项”继续。私有、空列表、受限或无法嵌入的内容仍可能失败。

B站的用户合集不等同于官方外链文档中的OGV seasonId。当前没有通过官方方法枚举普通合集，也没有可靠的父页面结束事件可触发下一项。可以一次导入多个BV/av号后手动切换；带 p 的分P地址仍可定位指定分P，但不会猜测总集数、自动p+1或承诺自动联播。平台播放器自身出现的内部联播选项由平台决定，页面不伪造控制。

### 小窗位置与大小

默认改为左上角；位置选择仍保留。新增“小窗大小”滑杆，目标宽度212至520像素，实际宽度会限制在播放区以内；调整时显示实际像素宽度。未调节前显示“自动”，按桌面／平板／手机选择初始尺寸。iframe视频区域始终保留至少200像素高度。调整通过CSS变量实现，不移动、不重建iframe，不重置计时。改变屏幕大小时会重新限制宽度。
